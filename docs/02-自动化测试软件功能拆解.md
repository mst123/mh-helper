# 梦幻西游手游稳定性测试：软件功能拆解

本文拆的是自动化测试软件本身要交付的功能。业务剧本（师门、抓鬼、周常等）见 `01-业务层拆解.md`。软件只通过系统提供的截图和模拟输入驱动客户端，不读取游戏内存，不修改安装包。

## 软件要解决的问题

业务层描述「测哪些玩法、怎样算过」。软件层要让这些流程能在一台电脑上的 5 个网易 Windows 客户端里同时执行，并且在认不准、超时、崩溃时停在可解释的状态，而不是盲点。每个账号的进度要在同一个监控页里看到。个别客户端跑在沙盒里，按「沙盒实例」一节单独处理。

建议分成五个部分：


| 部分    | 职责                   |
| ----- | -------------------- |
| 控制台   | 给人看设备、任务、日志和报告       |
| 设备执行器 | 管设备、启停应用、截图、注入点击     |
| 识别与动作 | 判断当前界面，并执行一次可校验的操作   |
| 流程引擎  | 按状态机跑用例，处理超时、重试和恢复   |
| 调度与报告 | 排 5 个账号同时跑、采集稳定性数据、出结果 |


## 1. 运行形态：一台电脑五个实例

可以。一台电脑同时测 5 个账号，做法是开 5 个网易 Windows 客户端，而不是用鼠标在 5 个窗口之间轮流点，也不使用模拟器。

- 每个客户端是一个窗口化进程，客户区尺寸一致，固定绑定一个账号
- 绑定键是窗口匹配规则。窗口每次启动都会变，开跑时重新查找，不把某次的窗口句柄写死在配置里
- 截图和点击都带这一路的窗口。点账号 A 时，输入只进入 A 的窗口
- 不依赖窗口焦点，也不截整块屏幕。某个窗口被点到前台、被拖动或被挡住，截图和点击仍然落在它自己的客户区。窗口缩在任务栏里时没有画面，直接说明窗口已最小化，不记成截图超时
- 5 路流程各自持有步骤指针。某一路挂起、崩溃或停止，另外 4 路继续
- 同一个客户端有两段标题。启动器阶段是 `MyPCLauncher_x64r`，点「开始游戏」后标题里会出现「梦幻西游」。这一路两种标题都要匹配。启动器画面上先认出「开始游戏」再点击。这一步只做 1 路，不扩到 5 开
- 登录页的账号下拉按客户区比例坐标点，因为框里的文字会变。点下去之后画面没有变化，就停住并说明列表没打开。列表里的账号和「进入游戏」仍用文字识别；列表没出现目标文字时，用滚轮往下翻再往上翻。
- 区服和角色保持画面上的默认项，不另选。先点「下一步」，再点「登录游戏」。
- 主界面用左下角「点击输入」或上方单独的「活动」两个字确认，有一个即可。活动推送会挡住画面。带「前往报名」或「联赛手册」的海报用 Esc 关掉。
- 玩法按文件分开。登录在 `tasks/login.py`，认角色在 `tasks/character.py`，师门在 `tasks/shimen.py`，宝图在 `tasks/baotu.py`，秘境降妖在 `tasks/mijing.py`。是否状态 A、是否战斗页、按 Esc 回状态 A、每 15 秒看画面中心，放在 `toolkit/`。文件对照见 `03-技术选型.md` 的「代码放哪」。
- 监控页先选任务，默认师门。执行中和暂停时不能改选。点开始后只跑这一个，回到状态 A 就停止。师门做完不自动做宝图。启动器或登录页会停住，提示先进入主界面。还没有角色记录才点头像。卡片上可以清除当前角色，或清除这个角色今日的完成标记。
- 选了宝图才做宝图。打开活动列表和师门相同。右侧是完成就回主界面并停。点参加后先认主界面「宝图任务」，没有再等店小二并点对话。之后隔 15 秒看战斗螺母或主界面任务名，两边都不是就用 10 秒判断无关弹窗。寻路和战斗内部先不做。
- 选了秘境降妖才做秘境。打开活动列表和师门相同。没有完成按钮，看活跃 x/25，推荐双倍时是 x/50，满了才记完成。否则点参加，经云乐游和可能出现的选副本，进选关。剩余次数是 0 也记完成。点进新技能后每 10 秒看自动战斗。连续两次不在且中间那块没变，才处理手动进战斗、失败或通关。失败不记完成，通关才记。
- 主界面只看右下角包裹图标，不看左上角颜色。还没有角色记录时，点右上角头像，在属性页的一小块里读名字和 ID。读不到就点属性框中心。再点信息框中心，在另一小块里读门派，然后按 Esc 回到主界面。页签按位置点，不认字。记录写在执行器的 `data/daily.json`，键是角色 ID。每个角色每天的师门只记一次，其他每日一次的任务以后共用这份记录。
- 师门这一轮先按几次 Esc，再用右下角包裹图标确认主界面，点活动框中心，认标题「活动」，再点日常活动。在列表范围内缓慢拖动翻页，用师门图标找卡片，同一行右侧近处橙色是参加、绿色是完成。完成就回到主界面并停。参加后用色块确认师门弹窗，直接点「去完成」或「继续任务」，不等画面停住。然后看福利弹窗，有就先 Esc，关不掉再点关闭。之后每 20 秒用中下一块和上一张比。没变时，完成色对上就按两次 Esc 回主界面；对不上就按一次 Esc，继续看。对不上就留下截图和原因。

资源上要保证 5 个客户端同时开着时，按窗口截图和识别仍然来得及。客户区尺寸保持一致，避免同一套识别规则对不齐。登录错开几秒到几十秒，避免 5 个号在同一秒挤进选服。

## 沙盒实例（必须单独处理）

直接启动的客户端和沙盒里的客户端不是同一种实例。大多数账号按上一节处理。配置里标明「跑在某个沙盒」的那几路，还要满足下面这些条件。某一路沙盒打不通时，只停这一路，其余客户端继续。

发现窗口：

- 绑定键是「沙盒名称 + 窗口匹配规则」。不用游戏安装目录，也不要按进程名抓到的第一个窗口
- 沙盒中的游戏进程，父进程可能是沙盒宿主，路径可能是沙盒里的虚拟路径
- 窗口标题可能带沙盒标记。匹配规则要能区分同机上的直接启动客户端和沙盒客户端

不要从磁盘判断进度：

- 执行器在沙盒外。它看到的安装目录，不是沙盒内客户端实际读写的目录
- 不读游戏目录里的配置、日志或账号文件来判断走到哪一步。进度只来自该窗口的画面

截图：

- 仍然只截这个沙盒窗口，不截整屏
- 沙盒若把画面放在独立桌面或隔离开，沙盒外按窗口去截会得到黑图或旧图
- 黑图、空图、与上一张完全相同且窗口无响应的图，都不能送去识别，更不能据此点击
- 这一路记为「沙盒截图未打通」，监控页写明原因

点击：

- 沙盒可能丢掉来自沙盒外的点击，而且不返回错误
- 开跑前做点击回环：不把窗口抢到前台，向该窗口送入一次点击，用点击前后的截图判断画面是否变化
- 回环失败则停止这一路的自动点击，原因写「沙盒未接收外部点击」
- 此时改为在同一个沙盒里运行点击代理。沙盒外的执行器只把「截图」和「点击客户区坐标」发给代理，识别、流程和调度仍在沙盒外
- 直接启动的客户端不做这个代理

进程是否还活着：

- 看这一路的游戏窗口是否还在、客户区是否还能截到新画面
- 不因为沙盒宿主进程还在，就认为游戏没退出。宿主还在时，里面的游戏可能已经崩溃

监控页：

- 卡片标明运行方式：直接启动，或沙盒名
- 「沙盒截图未打通」和「沙盒未接收外部点击」是单独状态，不记成普通超时或未知界面

## 2. 控制台

测试人员使用的本地页面。默认打开的是进度监控页。

- 进度监控页：同一屏看 5 个账号各自跑到哪
- 账号详情：点开某一个账号，看步骤时间线、最近识别和截图
- 启停控制：启动这一批、暂停一个实例、停止一个实例、只重跑失败账号
- 人工接管入口：某个实例挂起后，人可以处理完再交还流程

控制台不直接点游戏。它只向执行器下发命令，并展示执行器回传的状态。

## 3. 设备管理

- 发现本机的游戏窗口，显示匹配到的标题、客户区尺寸、是否沙盒、沙盒名、窗口是否还在
- 占用关系：一个窗口同一时间只跑一个账号，绑定关系可配置
- 开跑前检查：5 个窗口都能匹配到，客户区尺寸一致，绑定没有重复；沙盒实例还要通过截图和点击回环
- 健康检查：窗口是否还在、按窗口截图是否成功、截图是否为黑图
- 掉线处理：某个窗口消失后，只标记该账号失败并停在当前步，不把点击发到其余窗口
- 会话隔离：5 路各有独立的截图、日志和步骤指针



## 4. 应用控制

- 按客户端启动方式拉起：直接启动，或在指定沙盒中启动。停止时只结束这一路的游戏窗口
- 沙盒宿主如果还承载其他实例，停止一路时不要结束宿主
- 冷启动：结束该窗口后再拉起，单独统计启动耗时和结果
- 热启动：窗口仍在时继续使用当前窗口，单独统计
- 存活检测：每一步确认该游戏窗口还在，且能截到非黑画面。窗口消失记为崩溃并进入恢复
- 无响应检测：窗口还在但画面长时间无变化时，记为卡死候选，先截图再按恢复策略处理

不提供「清理账号数据后随意重登」这类会破坏测试现场的默认动作。需要重装或清数据时，作为单独、显式的维护操作。

## 5. 账号与测试数据

- 账号池：账号标识、绑定的窗口规则、是否沙盒、沙盒名、区服、角色、等级分组（低、中、高、脏状态）
- 敏感信息本地保存，不明文写进日志、报告和截图文件名
- 用例参数：该账号允许跑哪些日常或周常、开放时段、失败几次后停跑
- 进度：当前玩法、当前步骤、已重试次数、最近一次成功到达的安全点
- 导入导出：账号与设备绑定、用例开关可以导出；导出文件不含明文密码

软件只保存测试所需的账号配置。登录失效、顶号、二次验证时挂起会话并通知人，不自动绕过验证。

## 6. 画面采集

- 按该路窗口的客户区截取当前画面，作为识别和证据的输入。窗口被挡住时也要截到它自己的画面，不能截到叠在上面的其他客户端
- 截图与步骤编号、时间、窗口、是否沙盒、账号标识关联
- 黑图视为截图失败
- 可配置采样：每步必截，或仅在失败、未知界面、超时时截
- 截图失败视为该步失败，不允许在没有新画面的情况下继续点击
- 保留失败现场的最近若干张图，便于回放「点之前」和「点之后」



## 7. 界面识别

识别回答一个问题：现在是哪一屏。至少要能区分：

- 主界面
- 对话
- 寻路中
- 战斗中
- 结算
- 背包、任务栏、地图
- 全屏活动或过场
- 系统弹窗、公告、登录页、排队

能力要求：

- 模板匹配：按钮、图标、固定底板
- 文字识别：任务名、按钮文字、倒计时、提示语
- 区域特征：只在约定区域内查找，减少误匹配。监控台有「识别调试」页：任务停着时可以截当前窗口，也可以上传一张本地图换上。拖方框，或填四个比例再点识别，图上会画出这块，并认文字和颜色。调试不点击，也不改配置
- 输出界面名称、命中依据和置信度
- 置信度不足时定为「未知界面」，停止点击，截图并挂起或走恢复

识别规则与业务剧本分开维护。新增一个弹窗时，优先加一条识别规则，而不是改每一条玩法流程。

## 8. 输入模拟

只保留测试需要的输入：

- 单击
- 长按
- 滑动
- 游戏内返回（做在窗口客户区里的操作。Windows 客户端没有安卓返回键）

每次输入都是一次事务：

1. 截图并识别
2. 计算落点
3. 注入输入
4. 等待界面变化或到达预期状态
5. 超时则记失败，不追加盲目点击

不使用固定睡眠作为唯一步骤间隔。等待条件来自识别结果，例如「出现对话」「进入战斗」「回到主界面」。寻路和战斗允许更长的等待上限，但必须有超时。

## 9. 坐标与分辨率适配

- 落点使用相对坐标或锚点（相对某个已识别区域），不把某一台机器的绝对像素写死在流程里
- 设备接入时记录分辨率和显示区域，与基线不一致时拒绝开跑或先做换算校验
- 点击落在已识别目标的中心，并留出边距，避免点到相邻按钮
- 同一步在换设备后仍指向同一界面元素



## 10. 流程引擎

业务剧本落到软件里的执行模型。

- 用例由状态组成，状态之间按条件跳转
- 每个状态包含：进入条件、允许的动作、成功条件、超时、失败去向
- 支持子流程复用，例如「回到主界面」「关闭已知弹窗」「等待战斗结束」
- 上下文变量：当前任务、重试次数、是否已接任务、连续失败次数
- 可从中间恢复：重连后读取进度，先识别现场，再进入对应状态
- 跳过条件：玩法未开放时结束为「未开放」，不计为失败

引擎不理解具体玩法数值。它只执行「当前状态允许做什么、怎样算离开这个状态」。

## 11. 用例管理

- 用例列表：登录、师门、抓鬼、副本、周常等，可单独启用
- 用例版本：修改识别规则或步骤后可回溯
- 参数化：同一条「进入战斗并等待结算」供给多个玩法使用
- 依赖顺序：登录成功后才允许跑玩法；玩法之间默认互不写死顺序，由调度决定
- 调试运行：只跑一个状态或一个子流程，并保留每步截图

用例描述业务步骤。按钮长什么样放在识别规则里，点击怎么发出去放在输入模拟里。

## 12. 全局守卫

在每一步动作之前插入，所有用例共用。

- 已知弹窗：按优先级匹配，关闭或点确定，然后回到被打断的状态
- 未知弹窗：停止该账号，截图，记为阻塞
- 登录失效、顶号、二次验证：挂起，等待人工处理
- 进程消失：走崩溃恢复
- 同一状态超时：按该状态配置重试，超过次数后停止该账号
- 连续失败熔断：达到阈值后不再重试，避免死循环占住设备

守卫的优先级高于单条用例里的点击。用例不能在未知界面上自行继续。

## 13. 调度

面向一台电脑上 5 个账号同时跑的一批。

- 定时启动：每日跑日常，指定日期跑周常
- 错峰登录：5 个实例间隔启动，避免同一时刻挤在登录和选服
- 并发：默认 5 路一起跑，每路对应一个实例
- 玩法时段：未到开放时间的用例跳过
- 失败重跑：只重跑崩溃、超时、阻塞中被标记为可重试的账号
- 熔断后的账号从本批移除，其余实例继续
- 批次状态推给进度监控页：谁在跑、谁在等、谁已结束



## 14. 进度监控页

这是测试时一直开着的页面。5 个账号同一屏可见，不用逐个点进详情才能知道进度。

页面上方是这一批的总览：

- 批次状态：未开始、执行中、已结束
- 开始时间和已运行时长
- 五个计数：执行中、通过、阻塞、崩溃、超时
- 操作：开始本批、全部暂停、全部停止

页面主体是 5 张账号卡片，固定对应 5 个实例。每张卡片显示：

- 账号标识、角色分组、运行方式（直接启动或沙盒名）
- 当前状态：排队、执行中、寻路中、战斗中、挂起、通过、阻塞、崩溃、超时、未开放、沙盒截图未打通、沙盒未接收外部点击
- 当前玩法，以及玩法内部步骤，例如「师门 · 寻路 · 第 3 步 / 共 7 步」
- 本步已等待时间，接近超时时突出显示
- 已运行时长、重试次数、崩溃次数、断线次数
- 最近一张截图缩略图
- 最近一次识别结果和置信度
- 该实例是否在线

卡片上的操作只作用于这一路：暂停、继续、停止、打开详情。暂停或挂起某一张卡片时，另外 4 张继续更新。

点进详情后看到：

- 该账号本批的步骤时间线，每一步的开始时间、结果、截图
- 当前画面大图
- 挂起原因；若在等待人工处理，可以选「从当前界面继续」或「本账号本批停止」

刷新方式：执行器每完成一次识别或状态变化就推送，页面在约 1 秒内更新。截图缩略图可以按固定间隔刷新，避免 5 路同时传全尺寸图把页面拖慢。全尺寸图留在详情和证据目录里。

可选采集项从系统侧读取，不进入游戏进程：启动耗时、实例内存（若系统接口可用）。采不到则留空，不估算。监控页不展示密码和验证码。

## 15. 证据与日志

- 结构化日志：时间、设备、账号标识、用例、状态、动作、识别结果、判定
- 失败证据：动作前截图、动作后截图、超时或未知界面截图。出现未知界面、截图失败或需要人工时，最近 6 张图写到该路的 `error` 目录，状态变化追加到 `status.log`。同一个按钮点得太多就停手，不退出执行器
- 日志级别：正常步骤用简要记录，失败保留完整上下文
- 日志中不写入密码、验证码和完整账号凭据
- 单次批次的日志和截图放在同一目录，报告能反查到文件



## 16. 稳定性记录

软件要落库或落盘的原始记录：


| 字段      | 含义              |
| ------- | --------------- |
| 批次号     | 一次定时或手动开跑       |
| 账号标识    | 脱敏后的测试号         |
| 设备      | 执行设备            |
| 用例      | 登录、某个日常或某个周常    |
| 开始 / 结束 | 耗时              |
| 结束步骤    | 停在哪一个状态         |
| 结果      | 通过、阻塞、崩溃、超时、未开放 |
| 重试次数    | 本用例内重试          |
| 崩溃次数    | 进程消失            |
| 断线次数    | 观察到的重连或登录失效     |
| 证据      | 截图和日志位置         |


同一步骤、同一结果在多个账号出现时，报告里聚成一组，便于判断是客户端问题还是单号脚本偏差。

## 17. 报告

- 批次摘要：账号数、用例数、四类结果的数量
- 明细：账号 × 用例 × 结果 × 结束步骤
- 聚合：按用例看失败步骤分布，按设备看是否某台设备异常偏多
- 导出：本地报告文件，链到证据目录
- 对比：同一种用例与最近一次批次的通过率和超时步骤（有历史数据时）

报告描述现象和现场。不自动下结论说某一行游戏代码有缺陷。

## 18. 人工接管

- 挂起：停止向该实例注入输入，进度页上仍显示最后画面和挂起原因
- 接管原因要可见：未知界面、二次验证、连续低置信度
- 人处理完后选择「从当前界面继续」或「本账号本批停止」
- 接管期间的等待不记成脚本超时
- 其余 4 个实例不受这一路挂起的影响



## 19. 配置、权限与审计

- 环境配置：测试服、客户端启动路径、窗口匹配规则、默认识别阈值、默认超时、熔断次数
- 配置分环境保存，避免把测试服批次误发到其他环境
- 操作审计：谁启动了批次、谁停止了设备、谁改了账号绑定和用例
- 识别阈值、超时、熔断次数改动后对新批次生效，不悄悄改动正在跑的步骤



## 20. 通知

批次结束或出现熔断、崩溃聚集时通知测试人员。通知内容只包含批次号、结果计数和报告位置，不包含账号凭据和整屏截图。

## 21. 明确不做

以下能力不属于这套软件：

- 读取或改写游戏内存
- 注入游戏进程、挂钩渲染或逻辑
- 修改安装包、重打包
- 拦截或重放游戏协议
- 绕过登录验证、二次验证或客户端保护
- 用服务器测试接口代替点击来完成任务

稳定性结论只来自真实界面操作路径。服务器接口可以另做接口测试，但不放进这个软件的执行链路。

## 模块依赖

```text
进度监控页
  -> 调度
      -> 流程引擎
          -> 全局守卫
          -> 界面识别
          -> 输入模拟
              -> 窗口执行器（按窗口截图、点击、启停）
              -> 沙盒内点击代理（仅沙盒回环失败的那一路）
      -> 账号与进度
  -> 报告
      -> 日志与证据
      -> 稳定性记录
```

落地时按这个顺序做软件能力，业务用例往后加：

1. 单实例：连接、截图、点击、识别主界面、进程存活
2. 流程引擎：一个状态机能跑完「登录到主界面」，失败会停并留证
3. 全局守卫：已知弹窗和未知界面
4. 一台电脑拉起 5 个实例，进度监控页同时显示 5 路进度；某一路熔断不影响其余路
5. 再把业务文档里的师门、抓鬼、副本、周常接成用例

前四步没有完成时，不并行堆玩法脚本。玩法一多，没有识别置信度、超时和熔断的点击会变成不可解释的连续失败。
