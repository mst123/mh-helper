# 梦幻西游手游稳定性测试：业务层拆解

本文记录用模拟点击做客户端稳定性测试时，业务上要覆盖什么、怎么组织账号，以及日常和周常应该怎么拆。这里谈的是测什么，不谈测试软件本身怎么实现。

## 测试边界

这类测试适合覆盖客户端在真实操作路径上的长时间表现：

- 登录、选服、选角、进入游戏
- 场景切换、自动寻路、对话
- 进入战斗、战斗过程、战斗结算
- 界面来回切换、弹窗打断
- 断线重连、进程退出后再次进入

点击只能确认客户端表现，不能代替服务器测试接口。奖励是否入账、任务计数是否正确、经济系统是否平衡，都不在这套测试的验收范围内。

正式包上的模拟点击会碰到客户端自身的环境保护。内部稳定性测试应使用内部包，在测试服上跑。

## 账号分组

同一批在一台电脑上同时跑 5 个账号，按角色分工，不要 5 个号跑完全相同的脚本。账号池可以多于 5 个，下一批再换另外的号。

| 分组 | 用途 | 重点 |
| --- | --- | --- |
| 低等级号 | 主线、师门、基础副本 | 引导多、界面切换多 |
| 中等级号 | 抓鬼、宝图、秘境、日常副本 | 日常主循环 |
| 高等级号 | 鬼王、周常玩法、帮战或竞技入口 | 长时间战斗和匹配 |
| 脏状态号 | 背包满、任务栏满、有未领奖励 | 异常分支和阻塞 |

一台电脑同时跑 5 个账号：开 5 个网易 Windows 客户端，每个客户端绑定一个账号。点击送进对应窗口，不使用电脑鼠标去点当前获得焦点的窗口。个别客户端可以跑在沙盒里，这一路的连通性单独判断，失败时只停这一路。

## 日常与周常要压到的路径

玩法名会随版本调整。稳定性测试关心的是路径类型，不是把奖励刷满。

| 类型 | 代表玩法 | 重点压到的客户端路径 |
| --- | --- | --- |
| 日常短循环 | 师门、宝图、运镖、帮派任务 | 反复对话、寻路、交任务 |
| 日常战斗 | 抓鬼、秘境、日常副本 | 进战、回合、结算、再进战 |
| 周常 | 周常副本、门派闯关、竞技或帮战入口 | 匹配、长战斗、场景切换 |
| 活跃收尾 | 签到、活跃领奖、背包整理 | 界面堆叠和奖励弹窗 |

公共路径先统一，再按玩法填差异：

1. 接任务
2. 寻路
3. 对话或进入副本
4. 战斗
5. 结算
6. 交任务
7. 确认完成

每条流程做成独立状态机，不要写成一条从头到尾的长脚本。断线或重进后，先判断任务是否还在，再决定继续或重新接取。

## 业务侧必须处理的干扰

日常被打断，常见原因是界面而不是战斗逻辑。下面这些都要能识别，并在处理完后回到原任务：

- 活动推送、限时玩法入口
- 升级、成就、奖励领取
- 好友、帮派邀请
- 月卡或运营弹窗
- 未看完的引导

处理不了的弹窗记为阻塞，并留下截图。不要在错误界面上连续点击。

## 战斗与寻路的业务策略

稳定性测试不追求最优打法。

- 战斗使用游戏内自动战斗。脚本只确认是否进战、是否卡住、是否正常退出、回合是否异常变长。
- 寻路使用游戏内自动寻路。脚本负责点任务或点 NPC，再确认人物开始移动、到达、进入下一段对话。
- 要记录的缺陷包括：卡在空气墙、寻路中断、无法进战、结算界面不消失。

## 业务异常与恢复顺序

至少覆盖：

- 进程崩溃、无响应、闪退回桌面
- 断线、重连、顶号、登录失效
- 卡在对话、卡在寻路、卡在战斗结算
- 背包满、任务满、等级或次数不够，入口不可点
- 意外进入活动、观战、摆摊或全屏过场

恢复顺序固定为：

1. 截图
2. 记日志
3. 尝试回到主界面
4. 仍失败则重启客户端，再恢复该账号进度

同一账号连续失败要停掉该账号，避免一个死循环拖住其余实例。5 个实例里某一个挂起或停止时，另外 4 个继续跑。

未开放的玩法记为「未开放」，不要记成失败。日常和周常的开放时段不同，调度时要能跳过。

## 业务结果怎么判

每个账号、每条任务留下：

- 开始和结束时间
- 停在哪一步
- 重试次数
- 崩溃次数
- 断线次数
- 关键界面截图

汇总维度是「账号 × 任务 × 结果 × 证据」。结果只分四类：通过、阻塞、崩溃、超时。同一步骤在多个号上重复出现，才当成稳定性问题。

## 师门怎么进

代码在 `mh/runner/app/tasks/shimen.py`。认角色在 `tasks/character.py`，关弹窗和状态 A 在 `toolkit/`。

一轮师门从主界面的活动列表进，不点右侧任务追踪。重新上号后也要再看一次，任务栏里残留的师门进度不算已经在做。

1. 在主界面点右上角头像，打开人物属性。这里读角色名字和 ID。ID 是这个角色的唯一记录。再点右侧「信息」，读门派。门派先记下，后面用。读完按 Esc 回到主界面。
2. 点上方的「活动」，打开活动列表。
3. 点「活动」之后要看到「日常活动」才算列表打开，没开就隔开再点。点下去先等画面中心停住，再认下一屏。左侧点「日常活动」。在右侧列表里找到「师门任务」，只在这一行右侧认「参加」或「完成」。认不出字时，绿色按钮算「完成」，金色按钮算「参加」。是「完成」就说明今天做过了，关掉列表，不再做。是「参加」才点「参加」。师门在列表最底下。列表打开时不一定在头部，先向上滚到顶，再从头往下翻，直到列表不再动。窗口消息翻不动时，改用真实滚轮，光标在列表上停一下再放回。
4. 弹出师门面板后点「去完成」。上次做到一半时，按钮是「继续任务」，点它。只有点了这两个按钮之后，才算正在做师门。
5. 师门开始后客户端自己跑，不再点任务。点下「去完成」或「继续任务」之后，到出现「师门任务完成」之前，这段时间里的任务弹窗不能关。
6. 正在做师门时，每 15 秒看一次画面中心。连续两次中心几乎不变，说明无关弹窗卡住了，按一次 Esc。中心在变的是任务过程，不关。画面中间有「自动寻路」时不按，也不重新点参加。主界面本身不按。福利页和活动海报认出来就可以关。
7. 「师门任务完成」只在画面上半部认。出现后，或活动列表右侧已经是「完成」，把这个角色今天的师门记到本地。每个角色每天只记一次。宝图、运镖这类每天一次的任务以后用同一份记录。然后按 Esc 回到主界面。左下角「点击输入」或上方「活动」有一个，就算已经进了游戏。人物信息这类弹窗还开着时，先按 Esc 回到状态 A，再点「活动」。状态 A 是上方能看到「活动」、弹窗已经关掉的画面。已经在状态 A 时不按 Esc。没有结算弹窗不算失败。

## 宝图怎么进

代码在 `mh/runner/app/tasks/baotu.py`。师门这一轮结束后才做。参加、完成、继续任务和师门用同一套判断。

1. 点「活动」，再点「日常活动」，找到「宝图任务」。右侧是「完成」就记到本地，今天不再做。右侧是「参加」或「继续任务」才点。
2. 点开后先等画面停住，再等店小二的对话，点「听听无妨」，之后客户端自己跑。画面中间有「自动寻路」时不按 Esc，也不重新点参加。
3. 跑起来以后，状态 A 下点右侧「任务」，在任务栏里找「宝图任务」。找得到，就是正在做，或者已经接了但中断了。列表可以滚动。
4. 战斗页上方没有「活动」，右下角是「取消」或「自动」，有一个即可。手动战斗时显示的是「自动」。这页不按 Esc，也不点活动。头像是画出来的，不拿来判断。

## 业务落地顺序

1. 单账号跑通：启动、登录、识别主界面、关掉一层弹窗、完成一轮师门。
2. 补异常：杀进程后重进、断线重连、弹窗打断后回到任务。
3. 扩到一台电脑上的 5 个 Windows 客户端：同时开跑，并在进度页上看每个账号停在哪一步。若其中有沙盒客户端，先确认这一路能截到图、点得进去。
4. 再加抓鬼、副本、周常。每加一个玩法，只新增该玩法的状态机。
