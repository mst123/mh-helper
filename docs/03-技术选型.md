# 技术选型

本文对应 `02-自动化测试软件功能拆解.md`。运行形态是一台 Windows 电脑、5 个网易 Windows 客户端。仓库里放两个可运行部分：执行器和监控台。报告、启停、账号详情都是监控台里的页面，不再单独做第三个软件。沙盒只给标明沙盒的那几路增加一个点击代理。

## 结论

| 部分 | 选型 | 原因 |
| --- | --- | --- |
| 游戏客户端 | 网易 Windows 客户端，窗口化，5 个同时开 | 不用模拟器，也不用 ADB |
| 执行器 | Python 3.11 | 窗口截图、图像识别、中文 OCR 的库都集中在 Python |
| 找窗口和点击 | 枚举顶层窗口，再用窗口消息单击 | 按标题找窗口，多个时用枚举到的第一个。点击送进客户区，不移动鼠标、不抢前台 |
| 按窗口截图 | Windows Graphics Capture | 窗口被其他客户端挡住时仍截该窗口。PrintWindow 对这种画面经常是黑图，不用它当主路径 |
| 文字识别 | RapidOCR | 任务名、按钮文字、弹窗提示；模型体积比完整 PaddleOCR 小 |
| 沙盒 | 仅沙盒实例使用的沙盒内点击代理 | 沙盒外点击打不进去时，由代理在沙盒内截图和点击 |
| 执行器接口 | FastAPI + WebSocket | 本机给监控台提供启停、进度推送和截图 |
| 流程 | Python 状态机，步骤用 YAML 描述 | 超时、重试、恢复写在代码里；玩法步骤测试人员也能改 |
| 监控台 | Vue 3 + TypeScript + Vite + Element Plus | 进度页、详情、启停都是本地网页 |
| 实时进度 | WebSocket | 状态变化约 1 秒内推到 5 张卡片 |
| 数据 | SQLite + 本地截图目录 | 5 个账号的批次、步骤、结果；截图不进数据库 |
| 仓库 | `docs/` 与 `apps/` 同级 | 规格在 `docs/`，代码在 `apps/runner` 与 `apps/console` |

游戏画面是绘制出来的，按钮通常不在系统界面树上。执行器以「按窗口截图 → 认画面 → 把点击送进该窗口」为唯一操作路径。

## 两个软件怎么分工

```text
监控台 (Vue 3, 浏览器打开 http://127.0.0.1)
    |  HTTP：开始、暂停、停止、查询历史
    |  WebSocket：5 路进度、缩略图、挂起原因
    v
执行器 (Python FastAPI, 只监听本机)
    |  5 个并发任务，每个任务绑定一个窗口规则
    |  沙盒回环失败的那一路，改把截图和点击交给沙盒内代理
    v
窗口枚举 / Windows Graphics Capture
    v
5 个 Windows 客户端窗口
```

- 执行器拥有窗口、识别、状态机、调度、写 SQLite、存截图。
- 监控台只展示和发命令。它不计算点击坐标，也不操作窗口。
- 两边用 JSON。账号标识用测试编号，接口里不传密码。

监控台由前端技术栈来做。执行器留在 Python，是因为 5 路同时做模板匹配和中文 OCR 时，Python 侧的库可以直接用，不必在 Node 里再包一层。

## 执行器

- Python 3.11
- 枚举可见顶层窗口，按标题规则匹配。一个都没有就停在这一路并说明原因。多个时用枚举到的第一个
- 单击用窗口消息送进客户区相对坐标，不移动鼠标，也不把窗口切到前台
- 同一路可以写多条标题。标题是 `MyPCLauncher_x64r` 时，用 RapidOCR 在客户区截图里找「开始游戏」，点文字区域中心
- Windows Graphics Capture：按窗口句柄截取客户区，窗口被挡住时也不截到别的客户端
- OpenCV：固定按钮、图标用模板
- RapidOCR：会变的文字，例如任务名、次数、弹窗正文
- FastAPI：`127.0.0.1` 上的 HTTP 和 WebSocket
- SQLite：批次、账号绑定、每一步的结果
- PyYAML：每个玩法一份步骤文件

5 路并发用 5 个任务，每路一把窗口锁。同一窗口不会同时截图和点击。识别和点击都带这一路的窗口规则。

直接启动的客户端，开跑前做一次不抢前台的点击回环。回环通过就一直由沙盒外的执行器点击。回环不通过的窗口，按沙盒实例处理，不降级成移动真实鼠标。

模板负责稳定的界面元素，OCR 负责会变的字。置信度不够时，这一步停住并推「未知界面」到监控台，不继续点。

玩法步骤示例字段：状态名、进入条件、动作、成功条件、超时秒数、失败后去哪。师门、抓鬼、周常各一份 YAML，公共动作（回主界面、关已知弹窗、等战斗结束）写成可引用的子流程。

## 监控台

- Vue 3 + TypeScript + Vite，组件使用 `<script setup>`
- 组件库用 Element Plus，先把 5 张卡片和详情做出来
- 页面用 Vue Router：进度、详情、批次记录
- 这三页共用的批次状态用 Pinia
- 数据请求用本机 HTTP；进度用 WebSocket
- 开发时 Vite 把 `/api` 代理到 FastAPI

页面就三块，都在这个监控台里：

1. 进度监控：批次总览 + 5 张账号卡片
2. 账号详情：步骤时间线、当前大图、继续或停止
3. 批次记录：历史结果，链到本机截图文件

卡片上的暂停、继续、停止只带该实例的编号。

## 数据与截图

SQLite 单文件放在执行器数据目录，例如 `runner/data/app.db`。表按功能拆解里的稳定性记录来：批次、账号、用例、步骤、结果、证据路径。

截图按 `批次号/账号标识/步骤序号.png` 放在磁盘上。WebSocket 推缩略图或缩略图路径；详情页再取全尺寸图。

## 客户端约定

- 5 个客户端都使用窗口化，客户区尺寸相同，并在执行器配置里写明基线尺寸
- 账号绑定写窗口匹配规则、是否沙盒、沙盒名。不写某一次运行的窗口句柄
- 开跑前执行器重新查找窗口，检查客户区尺寸一致、截图不是黑图、绑定没有重复

## 沙盒实例怎么实现

只有配置了沙盒名的账号走这条路径。代理是一个很小的进程，职责只有两件：按命令截该窗口，按命令把点击送进该窗口。识别、状态机和监控推送仍然在沙盒外的执行器里。

1. 执行器先在沙盒外按窗口截图，并做点击回环。
2. 截图是黑图，或点击后画面没有变化：这一路改为启动沙盒内代理，执行器不再自己对这个窗口发点击。
3. 代理和执行器只在本机通信，消息内容是「截一张图」或「点击客户区里的相对坐标」。
4. 代理启动失败、代理截到黑图、或代理点击后仍然没有画面变化：这一路状态写成对应的沙盒失败，监控页展示沙盒名和原因。
5. 停止这一路时，结束该游戏窗口和该路代理。沙盒宿主还被其他实例使用时，不结束宿主。

## 仓库目录

规格和代码同级。第一期已经按这个位置落地。

```text
docs/                         业务拆解、功能拆解、本选型
apps/
  runner/                     Python 执行器
    requirements.txt
    config.example.yaml
    app/
    data/                     截图，不提交
```

`apps/runner/data/`、`apps/runner/.venv/`、`apps/console/node_modules/` 不提交。Python 依赖版本钉在 `requirements.txt`，前端锁定文件是 `package-lock.json`。

## 代码放哪

当前执行器在 `mh/runner/app/`。一个玩法一个文件，入口是 `run(slot, hwnd)`。改师门只打开师门那个文件。判断画面、关弹窗不要写进玩法文件。

| 文件 | 做什么 |
| --- | --- |
| `session.py` | 找窗口、截图、开始暂停停止。进游戏之后把画面交给登录或师门 |
| `evidence.py` | 状态写到 `status.log`。未知界面、截图失败或需要人工时，留下最近 6 张图。同一个按钮点太多次就停手 |
| `tasks/login.py` | 启动器「开始游戏」、选账号、默认区服和角色、确认已经进游戏 |
| `tasks/character.py` | 点右上角头像，读角色名字、ID 和门派 |
| `tasks/catalog.py` | 任务列表。监控页向这里要可选项，开始时只调用选中的那一个 |
| `tasks/prepare.py` | 开始前确认已在主界面。登录页、战斗、自动寻路会停住 |
| `tasks/shimen.py` | 师门 |
| `tasks/baotu.py` | 宝图。监控页选了才做 |
| `tasks/mijing.py` | 秘境降妖。监控页选了才做。进本后每 10 秒看是否还在自动战斗 |
| `toolkit/screen.py` | 主界面看右下角包裹图标。是否自动寻路、画面中心有没有停住。任务名右侧那一行单独认「参加」或「完成」 |
| `toolkit/dialog.py` | 按 Esc 回到状态 A；任务进行中每 15 秒看一次画面中心 |
| `toolkit/activity.py` | 师门和宝图共用：确认主界面，点活动，认标题，再点日常活动 |
| `toolkit/scroll.py` | 长列表翻页。账号列表用滚轮。活动列表在给定范围里按下缓慢拖动，拖完按页截图 |
| `toolkit/match.py` | 小图在截图里找位置。师门图标找到后，看同一行右侧近处按钮的颜色。`region_same` 比较两张图的同一块有没有变 |
| `toolkit/button.py` | 位置固定的按钮看一小块颜色。活动图标用它 |
| `toolkit/click.py` | 点「活动」之后要等到活动列表出现。点完先等画面中心停住，再认下一屏 |
| `daily.py` | 每个角色每天的完成记录，师门和其他每日一次的任务共用 |
| `inspect.py` | 识别调试。对截图或上传的图，按比例框认字并取样颜色 |

以后加宝图、运镖，新建 `tasks/` 里的一个文件，并从状态 A 调用它的 `run`。关弹窗和认状态 A 继续用 `toolkit`。

## 先做哪些

1. 已落地：执行器按窗口截一张非黑图，配置打开时不抢前台地点一下，并用 HTTP 和 WebSocket 把状态给监控台。
2. 已落地：监控台按返回的路数画卡片，能开始、暂停、停止，并显示直接启动或沙盒名。示例配置只有 1 路。
3. 进行中：监控页选择一个任务后开始，默认师门。只跑选中的任务，回到状态 A 后停止。请自己先登录并停在主界面，启动器或登录页会停住。开始按钮不再点登录。单路同时匹配启动器标题和含「梦幻西游」的标题。启动器「开始游戏」、列表中的账号、「进入游戏」、「下一步」和「登录游戏」用文字识别定位。账号下拉框里的文字会变，按客户区比例坐标点。区服和角色保持默认，不另选。账号列表用滚轮窗口消息翻动。点「登录游戏」之后，用左下角「点击输入」或上方「活动」确认主界面，有一个即可；带「前往报名」或「联赛手册」的活动推送用 Esc 关掉。进入主界面后先按客户区比例点右上角头像，读角色名字、ID 和门派，写到 `data/daily.json`。师门按测好的七步走：先按几次 Esc，用右下角包裹图标确认主界面，点活动框中心并认出标题「活动」，点日常活动，在列表范围内缓慢拖动翻页，用图标找师门。右侧是「完成」就记当天并回到主界面后停住；是「参加」就点，用色块确认弹窗，再点「去完成」或「继续任务」。有福利弹窗就先 Esc，关不掉再点关闭。之后每 20 秒比较中下一块，没变时用完成色决定是按两次 Esc 回主界面，还是按一次 Esc 继续。五开不在这一步。
4. 扩到 5 个窗口和 5 张卡片，确认某一路停止后其余路还在跑。其中至少一路用沙盒启动，并走通截图；若沙盒外点击无变化，再接上沙盒内代理。
5. 师门开始后的寻路、战斗，以及抓鬼等玩法，仍做成 YAML。五开和沙盒代理也在这之后。

## 暂不引入

- 独立的监控后端、Redis、MySQL。5 路进度用执行器内存状态加 SQLite 就够。
- 把执行器写成 Electron 或 Node。监控台保持网页，执行器保持 Python 进程。
- 为了找按钮去接游戏内部界面树或服务器测试接口。操作路径仍然是截图和模拟点击。
- 用模拟器或 ADB 驱动这个 Windows 客户端。
- 用整屏截图或真实鼠标在 5 个窗口之间切换焦点。
